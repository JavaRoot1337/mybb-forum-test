# Архитектура JavaRoot Resources

## Решение

Плагин остаётся модульным монолитом внутри MyBB. Legacy-файлы MyBB используются только как точки входа и адаптеры lifecycle/hooks. Внутренний код живёт в namespace `JavaRoot\Resources` и загружается собственным PSR-4 autoloader.

## Границы модулей

- `Lifecycle` отвечает за install, activate, deactivate, uninstall и настройки.
- `Service` содержит сценарии каталога, отзывов, избранного, жалоб, модерации, темы и загрузок.
- `Infrastructure\Database` содержит SQL и работу с таблицами `javaroot_*`.
- `Infrastructure\Storage` отвечает за путь хранения, временные файлы и проверку архивов.
- `Security` содержит права, allowlist и проверки входных данных.
- `Presentation` преобразует запросы MyBB в вызовы сервисов и формирует HTML/JSON/redirect-ответы.

Контроллеры не выполняют SQL и не принимают решений о доступе. Шаблоны и публичные URL остаются на прежних местах.

## Совместимость

Таблицы, поля, URL и значения `action` сохраняются. `SchemaManager` выполняет идемпотентную установку и только безопасные additive-изменения. Composer ядра не изменяется, чтобы пакет плагина оставался самодостаточным.

## Почему не Clean Architecture и не микросервисы

Для одного MyBB-плагина это создало бы больше косвенности, чем пользы. Репозитории применяются только там, где есть сложные SQL-запросы и несколько потребителей. Unit of Work не добавляется: текущая DB abstraction MyBB не предоставляет общего transaction API.

## Безопасность

Проверяются CSRF, владелец загрузки, срок действия токена, последовательность chunk-загрузки, canonical storage path, сигнатуры архивов, содержимое ZIP и список разрешённых внешних хостов. Ошибка финализации удаляет уже перемещённый файл.
